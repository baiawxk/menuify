# 系统模式

## 系统架构
```
核心组件
├── 配置管理
│   └── 配置加载 (unconfig)
├── 执行器系统
│   ├── 静态执行器（需要变量处理）
│   │   ├── Execa执行器
│   │   ├── Open执行器
│   │   └── Concurrently执行器
│   └── 动态执行器（自处理上下文）
│       ├── Function执行器
│       └── Listr2执行器
├── 工具函数
│   └── 字符串转换器
└── 类型系统
    ├── 静态类型定义
    └── 动态类型定义
```

## 关键技术决策
1. 执行器分类
   - 静态执行器：需要预处理字符串
   - 动态执行器：自行管理上下文

2. 变量处理
   - 简单字符串替换
   - 支持环境变量 (%VAR%)
   - 支持输入变量 ({VAR})

## 设计模式
1. 策略模式
   - 区分静态和动态执行策略
   - 明确处理边界

2. 工具函数
   - 纯函数设计
   - 简单直接的实现
   - 无状态处理

## 组件关系
1. 配置加载 -> 执行器选择 -> 任务执行
2. 用户输入 -> 配置处理 -> 执行器初始化
3. 执行器 -> 原生库调用 -> 结果处理

## 关键实现路径
1. 执行器处理流程
   ```
   配置解析 -> 执行器选择 -> 配置转换 -> 原生执行
   ```

2. 并行任务处理
   ```
   任务分组 -> 并行配置 -> concurrently执行 -> 结果聚合
   ```

3. 任务列表处理
   ```
   任务定义 -> listr2配置 -> 任务执行 -> 进度展示
   ```
